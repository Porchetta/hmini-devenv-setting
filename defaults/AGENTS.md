# 기본 작업 규칙 (모든 프로젝트 공통)

Claude Code와 Codex가 모든 프로젝트에서 함께 따르는 기본 규칙입니다.
프로젝트 저장소의 `AGENTS.md`나 `CLAUDE.md`가 이 규칙과 다르면 프로젝트 쪽을 따릅니다.
이 파일은 `hmini-devenv-setting/defaults/AGENTS.md`가 원본이고, `~/.codex/AGENTS.md`는 이 파일을 가리키는 링크입니다.

## 사용자

- 숙련된 Python 개발자입니다. 기초 설명은 줄이고 결론, 근거, 바꾼 내용을 먼저 말합니다.
- 대화와 문서는 한국어로 씁니다. 코드 식별자와 명령은 원문 그대로 둡니다.

## 작업 방식

- 시작 전에 목표와 완료 조건을 정합니다. 완료 조건에는 통과해야 할 명령(테스트, 린트)을 넣습니다.
- 저장소에 `STATUS.md`가 있으면 먼저 읽고, 작업을 멈추거나 한도에 가까워지면 갱신해 다른 에이전트가 이어받게 합니다.
- 새 동작에는 테스트를 같이 추가합니다. 테스트를 끄거나 건너뛰어서 통과시키지 않습니다.
- 추측한 내용은 추측이라고 밝히고, 확인한 내용은 무엇으로 확인했는지 적습니다.

## Python 기본값

프로젝트에 정해진 도구가 없을 때만 아래를 씁니다.

- 패키지와 가상환경: `uv` (`uv sync`, `uv run ...`)
- 테스트: `pytest`
- 린트와 포맷: `ruff check .`, `ruff format .`
- 타입 힌트를 쓰고, 새 코드는 지원 버전에 맞는 문법을 씁니다.

## Git

- 커밋과 푸시는 사용자가 요청했을 때만 합니다.
- 사용자는 개인 저장소에서 `main`에 바로 푸시하는 것을 선호합니다. 다른 사람과 같이 쓰는 저장소나 보호된 브랜치는 브랜치와 PR을 씁니다.
- 커밋은 작게 나누고, 메시지는 저장소의 기존 관례를 따릅니다.
- 강제 푸시, `git reset --hard`, 히스토리 재작성은 하지 않고 사람에게 묻습니다.

## 안전

- 설정값은 두 파일로 나눕니다.
  - `.env`: 포트, 호스트, 기능 플래그처럼 비밀이 아닌 값. 에이전트가 읽어도 됩니다.
  - `.env.confidential`: API 키, 토큰, 비밀번호 같은 비밀값. 읽거나, 출력하거나, 명령에 넣거나, 커밋하지 않습니다. 필요한 키 이름은 `.env.confidential.example`에 값 없이 적습니다.
- 앱은 `.env`를 먼저, `.env.confidential`을 나중에 읽어 비밀값이 덮어쓰게 합니다. 예: pydantic-settings는 `env_file=(".env", ".env.confidential")`, python-dotenv는 `load_dotenv(".env")` 다음 `load_dotenv(".env.confidential", override=True)`.
- 키 파일(`*.pem`, `id_*`)과 `~/.ssh`, `~/.aws` 같은 자격 증명 폴더도 읽지 않습니다.
- 배포, 데이터 삭제, 시스템 설정 변경, 외부로 메시지 보내기처럼 되돌리기 어려운 작업은 먼저 묻습니다.
- 패키지나 앱 설치는 사용자에게 명령을 알려 주고 직접 실행하게 합니다.

## 리뷰

- 의미 있는 변경은 마무리 전에 리뷰를 한 번 받습니다. Claude 세션에서는 `reviewer` 에이전트와 `/codex:review`, Codex 세션에서는 `reviewer` 에이전트를 씁니다.
- 리뷰 지적은 고치거나, 고치지 않는 이유를 남깁니다.
